# Website CRO Skill

## Purpose

This skill ensures that websites and landing pages are not only visually polished, but strategically structured to convert.

Use this skill when:

- building a new homepage
- building a landing page
- reviewing a weak or underperforming page
- improving CTA structure
- improving form completion rate
- improving service page clarity
- rewriting section hierarchy for conversions
- turning vague content into a conversion focused page

This skill must prioritize:

1. clarity
2. offer understanding
3. friction reduction
4. CTA visibility
5. trust and proof
6. objection handling
7. responsive usability

---

## Core Operating Rules

Claude must treat every page as a conversion system, not as a visual canvas.

Before building any section, Claude must identify:

- the page goal
- the target audience
- the primary action
- the primary offer
- the biggest likely hesitation
- the desired next step

Claude must not create sections just to make the page look full.

Every section must answer one of these:

- What is this
- Why should I care
- Why should I trust this
- What exactly do I get
- Why should I act now
- What removes my hesitation
- What do I do next

## Mandatory Page Logic

Every CRO focused page should usually include most of the following, depending on page type:

### 1. Hero

Must include:

- clear primary value proposition
- specific supporting sentence
- primary CTA
- optional secondary CTA only if justified
- visual that supports understanding, not distraction

Hero must answer in under 5 seconds:

- what this is
- who it is for
- why it matters

### 2. Trust Layer

Can include:

- logos
- metrics
- client count
- testimonials
- proof statements
- before and after indicators
- credibility markers

Trust should appear early if the audience is skeptical.

### 3. Offer / Services / Solution

Must clearly explain:

- what is being offered
- what is included
- how it helps
- how it differs from generic alternatives

Avoid vague labels like:

- premium solutions
- cutting edge services
- innovative digital excellence

Be specific.

### 4. Benefits

Translate features into outcomes.
Do not list features without explaining user gain.

### 5. Process / How it works

Must reduce uncertainty.
Best when the service or product requires commitment, trust, or a multi step process.

### 6. Objection Handling

Address common friction points such as:

- price uncertainty
- process confusion
- trust issues
- timeline concerns
- lack of technical understanding
- fear of wasting money

### 7. Social Proof / Testimonials / Results

Use proof that reduces doubt.
Proof must feel concrete, not decorative.

### 8. FAQ

Use only real questions that support decisions.
FAQ should reduce hesitation, not repeat generic marketing statements.

### 9. CTA Reentry

Strong pages reintroduce CTA after proof and after objections are reduced.

### 10. Footer CTA or Final Decision Push

End with a clear next step.
Do not end pages weakly.

## CTA Rules

There must be one primary CTA per page.
Secondary CTAs are allowed only if they do not compete with the primary goal.

Primary CTA must be:

- visible above the fold
- repeated throughout long pages
- written in action language
- aligned with commitment level

Examples of stronger CTA logic:

- Book a strategy call
- Get a custom quote
- Start your project
- Request a free audit

Avoid weak CTA language:

- Learn more
- Explore
- Submit
- Click here

Unless the page goal truly requires low commitment first.

---

## Offer Clarity Rules

Claude must make the offer understandable without requiring the user to infer meaning.

For service businesses:

- state who the service is for
- state what is delivered
- state expected outcome
- state how the process begins

For landing pages:

- state the transformation
- state the next step
- state why this solution is credible

Claude must avoid broad empty language.

---

## Form Optimization Rules

Forms should:

- collect only necessary information
- use clear field labels
- reduce friction
- support mobile usability
- appear where intent is strongest

Claude must not:

- overload lead forms
- ask for unnecessary data
- bury forms in weak page positions
- use ambiguous placeholders without labels

Preferred logic:

- short form for cold traffic
- slightly richer form for high intent traffic
- visible trust cue near form when appropriate

---

## Mobile CRO Rules

On mobile:

- CTA must remain obvious
- headline must remain readable fast
- spacing must not create fatigue
- cards must stack cleanly
- forms must be easy to complete
- proof and key points must remain visible without excessive scrolling confusion

Claude must design mobile for action, not only for appearance.

---

## Copy Rules for CRO

Copy must be:

- clear
- specific
- outcome oriented
- easy to scan

Headlines should focus on:

- result
- value
- transformation
- clarity

Subheadings should support understanding, not just sound polished.

Avoid:

- jargon without meaning
- inflated claims without proof
- vague agency speak
- overlong paragraphs

---

## CRO Review Workflow

When using this skill, Claude should follow this order:

1. Identify page goal
2. Identify target audience
3. Identify primary CTA
4. Map required sections
5. Define content purpose per section
6. Review friction points
7. Review trust gaps
8. Review mobile usability
9. Refine headline and CTA clarity
10. Ensure final page has a logical conversion path

---

## Output Requirements

When asked to create or improve a page, Claude should provide:

- recommended section structure
- brief CRO reasoning for each section
- suggested CTA logic
- suggested objection handling opportunities
- improved copy direction if needed
- implementation guidance if the task includes code

If asked to code, Claude must translate CRO logic into actual layout hierarchy, not just theory.

---

## When to Push Back

Claude should challenge requests that include:

- too many CTAs
- section bloat
- decorative elements with no conversion role
- weak headlines
- generic service descriptions
- unnecessary friction
- flashy design choices that weaken clarity

Claude should propose cleaner alternatives.
