# SEO GEO AEO Skill

## Purpose

This skill ensures pages are built and written in a way that is:

- discoverable in search
- understandable by search engines
- answerable by AI systems
- clear to human users
- aligned with page intent

Use this skill when:

- creating a homepage
- building service pages
- writing landing page content
- creating blog articles
- improving titles and meta descriptions
- adding FAQ sections
- planning internal links
- improving entity clarity
- preparing schema opportunities
- reviewing weak page structures for search visibility

This skill must prioritize:

1. page intent clarity
2. human readability
3. semantic structure
4. entity clarity
5. search relevance
6. answerability
7. trust and usefulness

---

## Core Philosophy

Claude must optimize for:

- clear intent
- direct communication
- semantic structure
- useful information
- clean topic targeting

Claude must NOT optimize for:

- keyword stuffing
- robotic repetition
- fake “AI optimized” fluff
- content inflation
- empty FAQ spam

The page must make sense to:

- a user
- a search engine
- an AI answer system

If content is unclear to a human, it is not truly optimized.

---

## SEO GEO AEO Definitions

### SEO

Optimize for search engines through:

- title relevance
- metadata quality
- page structure
- keyword and topic alignment
- internal linking
- useful content depth

### GEO

Optimize for generative engine understanding through:

- entity clarity
- topical structure
- explicit relationships
- direct statements
- source like clarity
- scannable explanation

### AEO

Optimize for answer engines through:

- concise answer blocks
- FAQ style clarity
- direct definitions
- intent matched sections
- structured, extractable content

Claude must treat these as overlapping systems, not separate gimmicks.

---

## Page Intent Rule

Before optimizing any page, Claude must identify:

- page type
- page goal
- primary topic
- target audience
- search intent
- desired next action

Common search intents:

- informational
- commercial investigation
- service or solution seeking
- navigational
- transactional

Claude must align content structure with the actual intent.

Claude must NOT:

- write informational content on a transactional page
- overload a service page with blog style filler
- confuse the user journey

---

## Topic and Entity Rules

Claude must clearly define:

- who the brand is
- what the page is about
- what service, product, or concept is being explained
- how the page relates to surrounding topics

Claude must reinforce relevant entities naturally through:

- headings
- body copy
- FAQs
- internal links
- metadata
- schema opportunities

Claude must NOT:

- force keyword repetition unnaturally
- use vague language when specificity is possible
- hide the actual topic behind branding fluff

Topic clarity must be visible within the first screen and throughout the structure.

---

## Content Structure Rules

Pages must use strong semantic hierarchy.

Claude must:

- use one clear H1
- use supportive H2 and H3 structure
- ensure each section has a clear purpose
- create scannable content
- write direct, extractable answers where relevant

Claude should:

- include short answer style blocks where useful
- use FAQs when they reduce friction or answer real questions
- write section intros that clarify the next content block

Claude must NOT:

- repeat the same point across multiple headings
- create fake depth through long filler paragraphs
- add FAQs that say nothing useful
- create heading structures that are visually nice but semantically weak

---

## Metadata Rules

Each page should have:

- one focused title tag
- one strong meta description
- one clear primary topic

### Title tag rules

Claude must:

- keep it specific
- align with real page intent
- include the primary topic naturally
- include brand only when helpful

Claude must NOT:

- stuff multiple keywords awkwardly
- create vague titles
- write titles that overpromise

### Meta description rules

Claude must:

- summarize the page clearly
- support click intent
- reflect what the user will actually get

Claude must NOT:

- write generic descriptions
- repeat the title mechanically
- add useless hype language

---

## Heading Rules

Claude must:

- use a clear H1 that matches page topic and intent
- use H2s to divide meaningful sections
- use H3s only when needed
- make headings understandable out of context

Claude must NOT:

- use multiple H1s unless technically justified and intentional
- create decorative headings that say nothing
- stuff keywords into every heading

Good headings help:

- users scan
- search engines parse
- AI systems extract structure

---

## Service Page Rules

For service pages, Claude must make sure the page clearly answers:

- what the service is
- who it is for
- what problem it solves
- what is included
- why this provider is credible
- what happens next

Service pages should usually include:

- clear hero
- service explanation
- outcomes or benefits
- process
- proof or trust
- FAQ
- CTA

Claude must NOT turn service pages into blog posts.
They must remain decision friendly and conversion ready.

---

## Homepage Rules

For homepages, Claude must:

- define the brand clearly
- explain what the business does
- reinforce target audience and value
- link into important service or content paths
- support both user understanding and crawl clarity

Homepages should support:

- brand entity recognition
- service discovery
- internal linking
- trust
- next step clarity

---

## Blog and Article Rules

For articles, Claude must:

- align tightly to one primary topic or question
- satisfy informational intent
- use structured headings
- answer the core question early
- expand with useful detail
- keep the writing scannable
- support internal links to related services or articles when appropriate

Claude should:

- include a concise direct answer early
- define terms clearly
- reinforce topic relationships naturally
- add FAQ only when relevant

Claude must NOT:

- create bloated article intros
- bury the answer
- write generic “in today’s digital world” filler
- over optimize by repeating the same phrase endlessly

---

## FAQ Rules

FAQs should only be used when they:

- answer real user questions
- reduce friction
- strengthen page clarity
- support answer extraction
- justify schema use

Claude must:

- write questions in natural language
- answer directly
- keep answers useful and concise
- avoid repeating content already obvious from the page unless clarification adds value

Claude must NOT:

- stuff pages with low value FAQs
- write fake questions no user would ask
- use FAQ only to cram keywords

---

## Internal Linking Rules

Claude must use internal links strategically.

Internal links should:

- connect related services
- support topical relationships
- guide user journeys
- reinforce content clusters

Claude must:

- link where contextually relevant
- use descriptive anchor text
- support discoverability of key pages

Claude must NOT:

- overlink every paragraph
- use vague anchors like click here
- add links without context

---

## GEO and AEO Formatting Rules

To improve answer engine and generative understanding, Claude should:

- define terms clearly
- answer important questions directly
- use simple, explicit statements
- avoid ambiguity where precision helps
- structure content in digestible sections
- make entity relationships easy to infer

Useful formats include:

- concise definition paragraphs
- question and answer blocks
- short summaries before deeper detail
- comparison sections
- process steps
- scoped FAQs

Claude must NOT write in a way that is only “search optimized” but not extractable or understandable.

---

## Schema Rule

Claude must identify when schema is appropriate, such as:

- Organization
- LocalBusiness
- Service
- FAQPage
- Article
- BreadcrumbList

Claude should:

- recommend schema when the page content truly supports it
- align schema with visible content
- avoid misleading markup

Claude must NOT:

- add schema that does not match the actual page
- create FAQ schema for thin or fake questions
- use structured data as a shortcut for weak content

---

## Local and Geographic Clarity Rule

When geographic relevance matters, Claude must:

- make location scope explicit
- state service area clearly
- keep local references relevant and natural
- align metadata and page copy with actual target location

Claude must NOT:

- stuff city names unnaturally
- create fake local relevance
- duplicate near identical pages for locations without real value

---

## Trust and Information Quality Rule

Search and answer visibility depends on trust.

Claude must:

- write precise claims
- avoid unverifiable hype
- support important statements with context
- make authorship, business identity, and service clarity easy to understand where relevant

Claude must NOT:

- inflate claims
- use fake authority language
- write pages that sound polished but say little

---

## Review Workflow

When using this skill, Claude should follow this order:

1. identify page type
2. identify page goal
3. identify primary topic and intent
4. define audience and search angle
5. structure headings semantically
6. refine content for clarity and usefulness
7. improve metadata
8. identify FAQ opportunities
9. identify internal linking opportunities
10. identify schema opportunities
11. review for extractability and entity clarity
12. remove fluff and repetition

---

## Output Requirements

When asked to optimize a page, Claude should provide:

- page intent summary
- recommended heading structure
- title tag
- meta description
- key content improvements
- FAQ opportunities if relevant
- internal linking suggestions
- schema recommendations if relevant

If asked to write content, Claude must produce:

- human readable copy
- structured headings
- clear topic alignment
- direct useful answers
- non spammy optimization

---

## When to Push Back

Claude should challenge:

- keyword stuffing requests
- fake FAQ sections
- vague titles and meta descriptions
- pages targeting too many topics
- service pages bloated with article style filler
- duplicate local pages with no real differentiation
- schema requests unsupported by visible content

Claude should propose a cleaner, more credible alternative.
